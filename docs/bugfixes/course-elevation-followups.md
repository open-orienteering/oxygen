# Course elevation: follow-ups after fix package 23

Left out of [course-elevation-review.md](course-elevation-review.md) on purpose.

1. **F1.** The holder does not refresh routes after a cloud-side out-of-bounds edit that arrives with the cadence map refresh (only after a `courseObject.*` write forwarded from the box). Wait for F2: with CRS-072 open it would re-search the whole event on the arena laptop after any map correction.
2. **F2 (CRS-072).** A local basis for the automatic routes (patch entries and objects whose box meets the leg's window) instead of the event-wide patch version; an `AUTO_ROUTE_VERSION` bump; the cases that must still change the basis (correction removed or hidden, patch on or off, a symbol's class). Spec §7.5 changes and a decision-log row.
3. **F3 (MAP-1 remainder).** Derive the fields at the confirmed interval (an artefact keyed on it, or a `TERRAIN_VERSION` bump) so the 3D view's vertical scale, the pick's `heightM`, the DEM anchor's level vote and its misalignment gate use it. Until then a map whose true interval differs from the guess may be refused a ground model as `misaligned`, and its coarse-DEM anchored field is not read for climb. Read the interval from an OMAP file if one turns out to carry it (D7 assumes none do).
4. **F4.** The Courses page says nothing when a course has no computed climb because the interval is unconfirmed; the printed and exported climb does not say it rests on contours.
5. **F5.** An event whose club map or club map version is deleted keeps the club map's confirmed interval on its own file row (copied before the delete). A restored event backup falls back to its own `map_files.contour_interval_m` (NULL: asked again).
6. **F6.** `course.update` and `course.bulkUpdate` with `firstAsStart` / `lastAsFinish` do not rebuild the `legs` string or a derived length (on main too).
7. **F7.** CRS-048's residual window (an edit committing between a chunk's read of the courses per pair and the pair's transaction); a failed pair's memo is per process, so a restart retries it once.
8. **F8.** Derived lengths are not re-derived on the holder after a map change during a lease (`venue-shipping-and-lease.md`, "Left out"); only climbs are.
9. **F9.** Not tried against Test-Eventor (EVT-22's first option): push once with and without the course element and record the result in `course-elevation.md` §0.38.
10. **F10.** Route refreshes of several events are not capped together; with one worker each it is one core per event.
11. **Q2 (done in the second review round).** `climbSource` and `winnerPaceSPerKm` now travel in `course.upserted` (removed from `COURSE_DERIVED_FIELDS`); an entry with `climbM` and no `climbSource` from an older sender is still held as typed. A peer built before 2026-11-25 would choke on the new keys, as the spec's "Readers" says receivers drop them since then.
12. **Not forwarded.** `clubMap.setContourInterval` is not cloud-owned: a box learns a changed club value with its next map refresh (the cloud's `enqueueContourInterval` skips events it does not hold).
13. **Tests not written.** The snapshot exporter's interval is covered by an integration test, not a unit test of its own.
14. **Showcase.** `e2e/showcase/editor.shot.ts` dismisses the interval banner; the shots are not retaken: retake hero shot.
15. **Anchored field after a confirmation.** Confirming an interval different from the assumed one drops the DEM-anchored field; if the plain contour field is not ready or over-cap the course has no computed climb until the field exists (the editor opened).
16. **Promote.** An event's own confirmed interval is not copied to a club map when its map is promoted to a version of it (the copy-up was dropped); the club map's value, if any, is the event's afterwards, otherwise it is asked again. A promote that changes the document clears and recomputes the computed climbs (holder only).
17. **DB-53 remainder.** `loadCourseSequences` still re-reads the start and finish per course (performance only). `chosenRoutesStamp` is the count and the latest `updated_at` in milliseconds: two writes in one millisecond that leave both unchanged would not show.
18. **Double header read.** `terrainDescriptor` and `heightfield` read the document header twice for the interval (performance only).
19. **Interval change during a lease.** A change made on the cloud while a box holds the lease is applied only when the box map-refreshes; if it never does before the lease ends, the box's climbs rest on the old interval. Idea: run `enqueueContourInterval` when the cloud regains the lease.
20. **Order of invalidation.** The editor invalidates its queries when the mutation returns, before the background recompute has run; a refetch can cache the old climb until the next one.
21. **Interval row hidden.** The row is hidden when the pick is the DEM-anchored row and the plain contour field is over-cap or none (`hasContours` false).
22. **Lease and atomicity.** The lease is re-checked per chunk, not per pair, in the route refresh; in `mapRefresh` and `contour-interval-apply` the check and the clear are separate statements, not one transaction.
23. **Residual compute window.** The compute's stamp check can pass just before an interval change commits while `clearComputedClimbs` has already picked its ids, so that one course keeps a climb at the old interval (milliseconds). Fix idea: clear by `climbSource = 'computed'` without the pre-read id list, or take the stamp under the row lock.
24. **Tests not yet written.** `eventsOnClubMap`'s `removed: false` filter is untested on its own, and no E2E drives `mayChange: false` (hidden controls); the integration test covers the flag.
