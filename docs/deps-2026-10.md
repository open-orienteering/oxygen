# October 2026 dependency sweep (minor / patch)

One PR against `main` raising every direct dependency to its latest minor
or patch release, refreshing the `pnpm.overrides` pins, and nothing else.
No major bumps — those are listed at the end and need their own PRs
(AGENTS.md §14). Previous sweep: [`migrations/2026-08-dependency-drift.md`](migrations/2026-08-dependency-drift.md).

## What moved

About 50 direct dependencies were behind on 2026-10-19. All `^` ranges were
raised to the latest release in their current major:

- **API**: fastify 5.12.7, @fastify/static 10.1.6, @fastify/cors 11.3.1,
  tRPC 11.19, Zod 4.6, mysql2 3.24, pg 8.23.1, fast-xml-parser 5.11,
  google-auth-library 11.3, proj4 2.22, pino-pretty 13.2, sharp 0.35.5,
  adm-zip 0.6.1.
- **Prisma 7.9.1 → 7.10.1** (`prisma`, `@prisma/client`,
  `@prisma/adapter-pg`). Drop-in: `pnpm db:generate` and the migration
  set are unchanged, integration and E2E suites pass.
- **Web**: React / React DOM 19.3 (and `@types/react{,-dom}` 19.3),
  TanStack Query 5.104, react-router-dom 7.18.4, i18next 26.5,
  react-i18next 17.1, Dexie 4.4.6. React 19.3 needed no code changes.
- **Tooling**: Vite 8.3, @vitejs/plugin-react 6.1, Vitest 4.1.12,
  ESLint 10.13, typescript-eslint 8.72, Playwright 1.64 (new Chromium
  build — run `pnpm exec playwright install chromium` after pulling),
  tsx 4.23.15, @types/node 26.6.

The lockfile was refreshed with `pnpm update -r` plus a targeted
`pnpm update -r --depth Infinity picomatch`, because `fdir` now wants
`picomatch@^4.0.7` as a peer and the tree still held 4.0.5.

## Playwright 1.64 / Chromium 156: compass permission

Chromium 156 ships `DeviceOrientationEvent.requestPermission()`, which
used to exist only on iOS. `useCompassHeading` takes that function to
mean "this platform gates the sensor", so on desktop Chrome 156 the
landing-page logo now starts as the tap-to-enable button
(`oxygen-logo-enable-compass`). Before, it rendered the live wrapper
straight away. Without a sensor grant, Chromium resolves the call with
`"prompt"`. The app counts anything other than `"granted"` as denied.

`e2e/event-selector.spec.ts` now grants `accelerometer`, `gyroscope` and
`magnetometer` and taps the button when it is shown, then checks the
live heading as before. The app code is unchanged. Whether desktop
Chrome should keep the iOS-style tap target is a product question for
a separate PR.

## Held back or removed

- **jsdom stays on 30.0.x** (`~30.0.1` in `@oxygen/api`, plus a
  `"jsdom": "~30.0.1"` override). jsdom 30.1.0 declares
  `class ChildrenIterator extends Iterator`, which needs the global
  `Iterator` from Node 22. On our Node 20 runtime (Dockerfile
  `node:20-slim`, CI `node-version: 20`) loading jsdom throws
  `ReferenceError: Iterator is not defined`, which breaks OCAD-to-SVG
  rendering in `course-maps/map-source.ts` (club map previews, course
  map PDFs). The override is there
  because vitest pulls jsdom in as an auto-installed peer, and without it
  `@oxygen/shared` resolved its own jsdom 30.1.3 copy. Lift both once the
  runtime moves to Node 22.
- **`@types/adm-zip` removed.** 0.6.0 is a deprecated stub: adm-zip 0.6
  ships its own `types.d.ts`, which TypeScript was already using.

## Overrides

Every `pnpm.overrides` value was raised to the newest release in its
series (for example `undici ^7.30.1`, `postcss ^8.5.31`, `rollup ^4.64.10`).
One selector also had to widen. `brace-expansion@>=3.0.0 <5.0.9` let
5.0.9 through untouched, and 5.0.9 is itself vulnerable (fix in 5.0.11).
It is now `brace-expansion@>=3.0.0 <5.0.11` → `^5.0.12`. The adm-zip
advisory (fix ≥ 0.6.1) is handled by the direct range bump. No override
was dropped.

`vite@<7.3.5` no longer matches anything, because the tree holds only
Vite 8. It is kept as a guard. It is also why pnpm reports
`unmet peer vite@^7.3.7` for vitest, @tailwindcss/vite and
vite-plugin-pwa: pnpm rewrites their `vite` peer range through the
override. That warning already shows on `main` and can be ignored.

`pnpm run audit:prod`: no high or critical advisory (none at moderate
either) in the 459-package production tree.

## Node 20 is falling behind

More of the tree now declares `engines.node >= 22`:
google-auth-library 11 / gaxios 8 / gcp-metadata 9 (already true on
`main`), and newly cookie 2 (via fastify → light-my-request) and
content-disposition 3 (via @fastify/static). They all run on Node 20
today: unit, integration, E2E and both Docker images pass. Node 20
reached end of life in April 2026, though, so jsdom will not be the last
package to need Node 22. Moving the Dockerfile and CI to Node 22 should
be its own PR.
