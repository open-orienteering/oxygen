The majors each get their own PR (AGENTS.md §14): Node 24, Playwright 1.65, Vitest 5, i18next 27, then vite-plugin-pwa 2 / dotenv 18 / GitHub Actions. Previous sweep: [`deps-2026-10.md`](deps-2026-10.md).

## 7-day release-age hold

`pnpm-workspace.yaml` now sets `minimumReleaseAge: 10080` (minutes). pnpm will not resolve any version, direct or transitive, published less than 7 days ago. A broken or compromised publish usually gets pulled within days, so the hold keeps it out of the lockfile. A security fix that can't wait is added to `minimumReleaseAgeExclude` with a comment.

# Part 2: Node 24 and pnpm 10.34

Node 20 reached end of life on 2026-04-30. More of the tree now needs Node 22 or newer (Vitest 5, i18next 27, react-i18next 18, jsdom 30.1+, google-auth-library 11, cookie 2, content-disposition 3). The runtime moves to **Node 24** (LTS "Krypton", supported until April 2028). Node 26 became LTS only in October 2026, so it can wait for the next bump.

- **`.nvmrc`** (`24`) is the single source of truth. Every `actions/setup-node` step reads it with `node-version-file: .nvmrc` (ci, release, audit-pr) instead of a hard-coded `node-version: 20`.
- **Dockerfile**: `node:24-slim` base. `scripts/__tests__/release-compose.test.mjs` looks for that line.
- **`engines.node`**: `>=22.12`. CI and the image run 24, but 22.12 is the lowest version the toolchain accepts, so a developer on 22 is not blocked.
- **pnpm 10.29.3 → 10.34.9** in `packageManager` and the Dockerfile. pnpm 10.34 refuses a tarball URL in the lockfile that has no `integrity` field unless pnpm knows the host as a git host. That is fine for the `codeload.github.com` ocad2geojson fork, but a local mirror of that tarball needs an `integrity` field.
- **jsdom override removed.** It pinned jsdom to `~30.0.1` because 30.1 needs Node 22's global `Iterator`. Nothing in the repo imports jsdom any more, and no Vitest config uses the jsdom environment, so the auto-installed peer drops out of the tree.

## Docker image smoke (new CI job)

The cloud container used for verification has no Docker daemon. Until now, CI built the image only on a push to `main` (`publish`). As a result, a runtime change was first proven when `:edge` moved. The new `image` job in `ci.yml` runs on every PR. It builds the `cloud` target for amd64 without pushing, then runs `packages/api/scripts/image-smoke.mjs` inside the image. The script loads `@resvg/resvg-js` and `sharp`, which the API imports lazily, so a broken binary would not stop the server from starting. It renders an SVG to PNG and resamples the PNG. The job also checks that the image's Node major matches `.nvmrc`. `publish` now needs `image`.
