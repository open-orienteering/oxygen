# November 2026 dependency sweep, part 1 (minor / patch)

The first of a stack of dependency PRs planned on 2026-11-20 after v0.9.0. This one raises every direct dependency to its newest minor or patch release in its current major, refreshes the lockfile and the advisory overrides, and adds a 7-day release-age hold. The majors each get their own PR (AGENTS.md §14): Node 24, Playwright 1.65, Vitest 5, i18next 27, then vite-plugin-pwa 2 / dotenv 18 / GitHub Actions. Previous sweep: [`deps-2026-10.md`](deps-2026-10.md).

## 7-day release-age hold

`pnpm-workspace.yaml` now sets `minimumReleaseAge: 10080` (minutes). pnpm will not resolve any version, direct or transitive, published less than 7 days ago. A broken or compromised publish usually gets pulled within days, so the hold keeps it out of the lockfile. A security fix that can't wait is added to `minimumReleaseAgeExclude` with a comment.

# Part 2: Node 24 and pnpm 10.34

Node 20 reached end of life on 2026-04-30. More of the tree now needs Node 22 or newer (Vitest 5, i18next 27, react-i18next 18, jsdom 30.1+, google-auth-library 11, cookie 2, content-disposition 3). The runtime moves to **Node 24** (LTS "Krypton", supported until April 2028). Node 26 became LTS only in October 2026, so it can wait for the next bump.

- **`.nvmrc`** (`24`) is the single source of truth. Every `actions/setup-node` step reads it with `node-version-file: .nvmrc` (ci, release, audit-pr) instead of a hard-coded `node-version: 20`.
- **Dockerfile**: `node:24-slim` base. `scripts/__tests__/release-compose.test.mjs` looks for that line.
- **`engines.node`**: `>=22.12`. CI and the image run 24, but 22.12 is the lowest version the toolchain accepts, so a developer on 22 is not blocked.
- **pnpm 10.29.3 → 10.34.9** in `packageManager` and the Dockerfile. pnpm 10.34 refuses a tarball URL in the lockfile that has no `integrity` field unless pnpm knows the host as a git host. That is fine for the `codeload.github.com` ocad2geojson fork, but a local mirror of that tarball needs an `integrity` field.
- **jsdom override removed.** It pinned jsdom to `~30.0.1` because 30.1 needs Node 22's global `Iterator`. Nothing in the repo imports jsdom any more, and no Vitest config uses the jsdom environment, so the auto-installed peer drops out of the tree.

## Docker image smoke (new CI job)

The cloud container used for verification has no Docker daemon. Until now, CI built the image only on a push to `main` (`publish`). As a result, a runtime change was first proven when `:edge` moved. The new `image` job in `ci.yml` runs on every PR. It builds the `cloud` target for amd64 without pushing, then runs `packages/api/scripts/image-smoke.mjs` inside the image. The script loads `@resvg/resvg-js` and `sharp`, which the API imports lazily, so a broken binary would not stop the server from starting. It renders an SVG to PNG and resamples the PNG. The job also checks that the image's Node major matches `.nvmrc`. `publish` now needs `image`.

## Verification

On Node 24.22.3 in the cloud: build, lint (0 errors), unit (same counts as part 1), `test:scripts`, integration, the image-smoke script against the installed tree, and full E2E. The image itself is proven by the new CI job.

# Part 5: i18next 27 and react-i18next 18

i18next 26.7.2 → **27.1.1** and react-i18next 17.1.13 → **18.0.1**, in the root and in `@oxygen/web`. The two have to move together, because react-i18next 18 needs i18next ≥ 27.0.1. The 7-day hold picks 27.1.1 (2026-11-10) over 27.2.2. i18next published eleven 27.x releases in its first 12 days, so if something regresses here, look at the newer 27.x patches first.

Checked against the i18next 27.0.0 and react-i18next 18.0.0 breaking changes:

| Change | Effect here |
|---|---|
| `fallbackLng` default `false` (was `dev`) | none: `i18n.ts` sets `fallbackLng: "en"` |
| `returnEmptyString` default `false` | none: no locale has an empty string |
| `/` no longer escaped; `Trans` always decodes entities | none: `escapeValue: false` is already set; one `<Trans>` (`OtherVariantBanner`) |
| objects without `returnObjects` treated as missing; dotted `getResource`/`addResource`; `createInstance` | none: not used |
| language codes canonicalised (`EN` → `en`), unsafe codes refused | none: codes are `en`/`sv` |
| `useTranslation`'s `i18n` forwards to the instance | none: `[i18n.language]` dependency arrays still change, because each render reads the current value |
| **types: `strictInterpolationChecks` defaults to `true`** | four build errors: the status, course-info and map-info row builders (`lib/editor/status.ts`, `map-info.ts`) and `EditorPage`'s action hints take a narrowed `t` whose options are optional. `src/i18n/i18next.d.ts` sets `strictInterpolationChecks: false`, which keeps the v26 types. Turning it back on means typing those wrappers with `ParseKeysWithoutVariables`. That is a separate change. |

No runtime code changed. Build, lint and unit tests pass on Node 24. In E2E, `event-selector.spec.ts` switches language. A Swedish/English spot-check by hand is part of the review.

# Part 7: minimatch and glob advisories

Two moderate Dependabot alerts were still open after parts 1 to 6, both on dev-only transitive packages:

- **minimatch** ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), globparts amplification DoS): vulnerable `>=7.0.0 <11.0.1`, no backport to the 9.x or 10.x lines. The tree had minimatch 9.0.9 (`ejs` → `jake` → `filelist`, already forced up from 5.x by the old `minimatch@<9.0.7` override) and 10.2.6 (`@typescript-eslint/typescript-estree` 8.72.2, and `glob` 11 below).
- **glob** ([GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4), AbortSignal cancellation bypass): vulnerable `>=9.0.0 <=14.0.1`. The tree had glob 11.1.0 from `workbox-build` 7.4.1 (via `vite-plugin-pwa`).

The lockfile refresh in part 1 could not clear them because the parents pin the old majors: `workbox-build` 7.4.1 is its latest release and still declares `glob ^11.0.1`; `filelist` 1.0.6 declares `minimatch ^5`; and the first `typescript-eslint` that moves to `minimatch ^11.0.1` (8.73.0) was published on 2026-11-16, so it is still inside the 7-day release-age hold.

Fix, in the root `pnpm.overrides`:

- `"minimatch@<11.0.1": "^11.0.1"` replaces `"minimatch@<9.0.7": "^9.0.9"`. Every minimatch in the tree is now 11.0.8 (the version eslint already used).
- `"glob@>=9.0.0 <14.0.2": "^14.0.2"` (new). glob 14.0.6 was already in the tree for `@fastify/static`. The lower bound keeps any future glob 7/8 consumer (a different, callback API) out of the override.

Compatibility checked: `filelist` calls `require('minimatch').match`, which minimatch 11's CommonJS build still exports; `workbox-build` only calls `globSync(pattern, { cwd, follow, ignore })`, unchanged in glob 14. The web build's service worker precaches the same 73 entries (4463.86 KiB) before and after.

When `typescript-eslint` 8.73+ and a `workbox-build` on glob ≥ 14.0.2 are available, the overrides become no-ops for those paths and can be dropped once nothing else needs them.
