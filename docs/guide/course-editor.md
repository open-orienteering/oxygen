# Course editor

Setting courses on the map: placing controls, legs, forks, loops, descriptions and the editing tools. This page is the detail behind the [feature tour](../features.md).

The Course Editor (overflow menu) turns the map into an editing surface with contextual actions — no tool switching: click empty map and a floating menu offers **Add control** (the next unused punch code from the club control series, or the smallest free code ≥ 31 if none are defined / all are used) or **Add to course**; click an existing control for **Add to course**, **Radio**, **Edit description** and **Delete**; click a course leg to **Insert into course** at that spot. A standalone collapsible inventory card shows every club series with used/free and SRR state and lets you pin code assignment to a specific series instead of the priority order; enabling radio on a non-SRR code offers an inline swap to the first free SRR unit. The same empty-map menu offers **Add start** and **Add finish** — auto-named "Start 1" / "Mål 1" and shown by that name; each takes the lowest free unit code from 3 (1 is clear, 2 check; 3–10, then 11–30), the code its start / finish unit is programmed with — and works on a brand-new event with no controls at all (the click transform comes from the map's calibration). With several starts placed, selecting one offers **Use as start for [course]**, so different courses can start from different points. Drag any control to move it — if it's shared, an amber chip warns which other courses the move affects, and the selection menu shows "Also in: …". Drag a control number to park it off the auto-placed slot (per course; **Reset number position** restores auto-placement). Click a punch code in the course panel to rename the control itself. **Edit description** opens a full IOF control-description editor: symbol pickers for every sheet column with English/Swedish tooltips, a dimensions field, and a live preview row. A floating panel over the map builds whole courses: create or clone a course, click it to edit, reorder or remove controls, and undo/redo sequence edits with `Ctrl+Z` / `Ctrl+Shift+Z`. Legacy first-as-start / last-as-finish flags remain honored by geometry and export but are now read-only badges on the Courses page. Pencil icons on the Courses and Controls pages deep-link straight into the editor. Positions are stored in map millimetres and converted to WGS84 server-side; moving a control rebuilds every affected course. Two people editing the same course or control no longer overwrite each other silently: an edit made from a copy that someone else has since changed is refused, the page reloads the row and says **Changed elsewhere — reloaded** (course editor and Courses page alike; see [course-layer.md](../course-layer.md) §7). A controller can be given a role with only view + review rights: they can check off controls and leave notes without being able to move them (see [system/authentication.md](../system/authentication.md)).

**Course editor.** Every event opens the course editor on the same GL canvas the maps are drawn on (since v0.6.0; an event without a map opens it too, with the map panel's upload prompt; outside fullscreen it takes the whole window, its width and its height, while the other tabs keep their boxed width): a top bar (course picker, Course / All controls view, mode switch Course · Layout · Field — undo / redo, hide other controls, auto cuts), a tool rail, an action bar under the selection with the same actions as before, an inspector beside the map (course sequence with per-leg metres, ↑ / ↓ and drag-to-reorder, the course's description-sheet instructions — the finish variant 14.1 / 14.2 / 14.3 with an optional finish length, and special-instruction rows such as a taped route after the start or a map exchange after a control —, the selected control's properties, the series inventory). The top bar also shows whether your edits are saved — a small green dot that turns into red words when a save fails or someone else changed the same thing, so a problem is never hidden — and a course-info button that opens the course's controls, length, climb, the shown sheet's print scale and paper, and number of checks — the climb is computed from the map's heights along the course (with its share of the length, for the 4 % rule of thumb) and saved with the course, so the description sheet and the IOF export state it too, unless one was typed in the course's **Climb (m)** field on the Courses page or came with an imported file — that one is the course's until the field is emptied; on a map without a ground model it comes from the map's contours and says it is approximate, and a selected leg shows its own length, climb, descent and height difference; **Show elevation profile** in the same popover opens a height graph of the whole course under the map — the controls marked along it, the selected leg shaded; move the pointer over it to read the height and see the place as a dot on the map, click to select that leg. A selected leg also lists its **Routes**: **Draw route** lets you click the way a runner would really take between the two controls (Enter saves, Esc cancels), and the course's climb is then read along that route instead of the straight line — the course's length and the printed line stay as they are, and the route is shared by every course that runs between those two controls in that direction; choose **Drawn line** to go back, ✕ to remove a route; **Find routes** searches the map for the fastest way between the two controls, up to two other ways that are nearly as fast, and the shortest way that crosses nothing uncrossable — each with its metres, climb and an estimated time at the pace you type (minutes per km on flat, runnable forest), drawn dashed on the map; **Use** keeps one as the leg's route. The times are rough estimates until the speed model has been calibrated against real GPS tracks, and bridges, tunnels and stairs are not understood yet; the editor has no status bar and no map footer under the map, so a small laptop screen keeps its room for the map (on a phone the same figures and the map scale stay in the bottom sheet). When the top bar's row runs short (a laptop screen, a narrow window) it makes room instead of wrapping: first **Hide other controls**, **Auto slits**, **Hide descriptions**, **Export** and the course picker's *Course* word drop their text and show their icons alone, then the **Course · Layout · Field** switch shows three icons (a start triangle and control, a printed sheet, a control flag) with the word in its tooltip; the view buttons keep their words. A **map icon** beside Export opens the map info: the map's name, scale, north lines, file and document details (format, objects, symbols, colours, symbol library, coordinate system), and the map's actions **Review symbols**, **Replace map** and **From club library**. Clicks hit the drawn map symbols themselves — a control by its whole circle, a leg, a number. Every edit saves at once and is one undo step; when someone else changed the same course or control meanwhile, a move is re-applied on top of their change when they did not move it too, otherwise the editor shows both positions or reloads and names what changed. The top bar lists who else has a course open and in which mode ("Anna · Lång · Field"); a course changed by someone else while you look at it re-renders with a one-line notice naming who and when, and a move that met a move shows "Moved by Anna at 12:41". See [course-editor.md](../course-editor.md).

**The editor's address follows it.** The address bar shows the course, the mode (Layout, Field), the view (All controls, a class, a variant, All variations) and Layout's sheet or template, so a reload or a link you send someone opens the editor the way you left it. Changing them does not add browser history: Back leaves the editor in one step. What you have selected, the tool and your display preferences stay out of the address. A link to a course, class or sheet that no longer exists simply opens the editor without it. See [course-editor.md](../course-editor.md) §1.

**Variations and loops in the editor.** Select a leg and choose **Create variation here**: the leg becomes a variation (gaffling) with alternatives A and B, both empty at first, so nothing moves on the map until a control is placed. The inspector shows the variation as a block in the sequence with a tab per alternative — click a tab (or press `1`–`9`) to show that alternative; an armed `K` then places controls into it, and clicking a leg of the alternative inserts there. The block adds, renames and removes alternatives, moves a dragged row into an alternative by dropping it on its tab, and its **Loop** box turns the variation into a butterfly whose variants run every alternative in each order. The top bar's **Variant ▾** shows one variant numbered as it prints, and **All variations** draws every alternative at once, each in its own purple tint — on screen only; a printed map is always one variant. When the alternatives are equal — every control has the same number whichever way the runner goes — the controls are labelled by number (both controls of a fork are 2), otherwise by code, as with loops and unequal forks. The checks warn when the alternatives' lengths differ by more than 10 %, and when a variation still has no controls. The course picker lists courses, not their variants. See [course-editor.md](../course-editor.md) §12.

**Printing variants.** A course with variations prints as its variants: **Export ▾ → This course (4 variants)** gives one page per variant on the course's sheet — the same layout and map window for all, each with its own course, numbering and description block, named "Long AB" — and **This variant AB · 12** prints the variant on screen. **All variations** prints one page per sheet with every alternative in the course purple, for the officials — numbered like the screen view when the alternatives are equal (the description block then lists the shared numbers, a fork's two controls both 2), else by code. **One map per runner** prints the hand-out stack: each variant's page once per runner assigned to it, variants in order, so the stack comes out sorted (the URL takes `&spare=n` for extra copies each). In Layout mode and Class view the sheet is drawn as one variant — the first by default; **Variant ▾** picks another without leaving the mode. The Courses page prints a variant from its row and the course's all-variations page from the course's row. A template's `{variant}` text shows the key. Maps are not printed with the runner's name. See [course-print.md](../course-print.md) §4.6.

**Layout mode (new editor).** The mode switch's **Layout** shows the course's printed sheet as the view: the paper, its printable margin, the map frame and the page's texts, white-outs, images and description block, drawn on the map canvas exactly as the PDF prints them (the map outside the frame is cut away). Click a text or shape to select it (a polygon or line by its outline, so a click inside a polygon reaches what is under it), drag to move it, drag a corner to resize it; a polygon is **drawn click by click** with `P` — each click a smooth point, Alt-click a corner, click-drag to shape a curve — and edited as in the course editor (drag a vertex or a handle, Alt-click a vertex to switch it between smooth and corner, double-click an edge to add a smooth vertex — Alt for a corner — Delete to remove the clicked one); select the frame and drag it to **align the map** — the saved window moves with it. A rail places header text, text, images from the graphics library, the description block, white-outs, lines, rectangles and polygons; the inspector edits the print scale, the block and the selected object's text, size, colours and fill, and lists what would print outside the page; a shape's fill can also be set to *White-out outside* (white everywhere in the frame except the shape — map text, out-of-bounds areas and the course included, on screen and in the PDF, like the course toner saver) — there is no tool for it, the course toner saver covers that need. The template's shared objects are locked on a course's sheet, with a link that opens the template itself (paper, orientation, scale, margin, symbol sizes). Every change saves at once and is one undo step. The inspector also renames a sheet, adds a second one (map exchange) or deletes it, creates a sheet for a course without one and the all-controls sheet (view *All controls*), renames, creates and deletes templates, and holds the **club templates** (bring one into the event, delete one, save the shown template); **Export ▾ → This sheet** prints the shown sheet. **Edit layout** on the Courses page opens Layout mode. See [course-layout.md](../course-layout.md).

**Templates by key, class sheets and Export ▾ (new editor).** A map template is identified by its paper, orientation and print scale (shown as an **auto** / **extra** badge on the Courses page and in Layout mode — existing templates keep their names). The first time a course needs a sheet — **Export ▾ → This course** in the editor's top bar, or the course's PDF button on the Courses page — Oxygen creates it on that key's template, making the template (named like "A4 portrait 1:10000") if the event has none, with the event's usual paper and scale and the orientation that holds the course. In Layout mode a setter can **Create extra template** for a course that needs a different layout and move courses between "courses in this template" and "other courses at this scale" by drag. A class can print its course at another scale or on another template (the **Classes** section in Layout mode); it then gets its own sheets, the editor's **Class** view shows the course as that class prints it, and **Export ▾ → This class** prints it. Export ▾ also offers all courses, all controls (the all-controls sheet is made the same way when the event has none), IOF XML and Purple Pen. Two setters saving the same sheet or template no longer overwrite each other: the second is told it changed elsewhere and redoes the edit. See [course-layout.md](../course-layout.md) §5–§7.

**Setter maps** (new editor). Layout mode's **Setter maps** section splits the event's placed controls — or, with a course picked, that course's — into as many groups as there are setters, by area: the same controls always give the same groups, numbered west to east. Each group gets its own A4 sheet, turned and scaled (1:4 000 to 1:15 000) so its controls fit with a margin, drawing only that setter's controls with their codes, the map-issue points among them, and a description block of those controls at 5 mm cells. **Move to next setter** beside a control on an open setter map hands it to the next setter (undo hands it back); **Recalculate** refits a setter map — or the all-controls map — to its controls and centres it again; **Regenerate** starts over. **Export ▾ → Setter maps** prints every setter map, one page each. In Field mode the control list can show a setter map instead of the course: pick it above the list, and the list becomes that setter's controls with distance, bearing and check-off, and "Setter 1 · 2/7 checked". See [course-layout.md](../course-layout.md) §8 and [course-editor.md](../course-editor.md) §9.

**Field mode** (new editor). On a phone the editor opens in Field mode, full screen: the setter's GPS position with its accuracy ring on the map, a compact top bar (back, course, mode, a ⋯ menu with undo / redo and the view options) and a bottom sheet that slides between a peek row — the course's controls, length and "3/12 checked", the selected control and its actions as large buttons — and half / full height with the control list: every control of the course with its distance and compass bearing from where you stand, and a tick to check it off. A floating **+** arms the control, start, finish, text and area tools in the pin-drop flow. Touch is made for the forest: a drag on a control pans the map unless that control is selected, a long press picks a control up and moves it, drawn above the finger so the finger never hides it, with a magnifier loupe above it that shows the spot at 2.5× while the finger moves; two fingers always pan and zoom. A nudge pad moves the selected control by 0.1 mm or 1 m, or to typed coordinates. Field mode is on the desktop's mode switch too. Offline, moves, nudges and check-offs are kept on the device — shown on the map and in the list at once, counted in the sheet ("Offline — 2 changes waiting to be sent"), and still there after a reload — and sent in order when the connection is back; if someone else moved the same control meanwhile, the editor says "Moved by … at …" and asks which position to keep, and a change the server refuses stays with Retry and Discard. Creating new controls still needs a connection. See [course-editor.md](../course-editor.md) §9–10.

**Map mode** (new editor; desktop). The mode switch's **Map** corrects the event's map without changing the club's map file: click a map object to select it — it lights up blue, and the inspector shows its symbol number, name and swatch — **Tab** steps through everything under the click (a path, then the area beneath it), **Delete** or **Hide** hides it, and dragging it moves it. Every change is saved at once and is one undo step. **H** hides the course overprint so the map shows on its own, **F** fits the whole map. The **Corrections** list shows every change made to the map; a click finds the object, **Revert** undoes that one change, and **Apply corrections** turns them all off and on again — off, the screen, print and the venue draw the map as it was, and the list keeps them. Course edits are locked while in Map mode. **N** (the rail's second tool) edits the nodes of the selected line or area: drag a node or one of its Bézier handles, double-click the edge to add a node (smooth; Alt for a corner), Alt-click a node to switch it between corner and smooth, and **Delete** removes the node you clicked — each one undo step, the map redrawn as you drag. The rail's magnet snaps a dragged node onto nearby map features (0.5 mm). Objects with more than 2000 nodes, points and texts have no node editing; the inspector says why. When the event's map is replaced by a new edition, re-imported or updated, the corrections follow their objects onto the new map: the same file's objects exactly, another edition's by place and symbol (within half a millimetre). Those that find no object or symbol are kept under **Not carried over**, drawn nowhere: a click shows where it was, **Attach** puts one onto the object selected on the map — or, when its symbol is missing, onto a symbol you pick — and **Drop** discards it, each one undo step; moving back to the first map brings them back. See [course-editor.md](../course-editor.md) §13 and [map-patches.md](../map-patches.md) §4. **Save corrections to the club map**: on an event whose map comes from the club library, Map mode's **Club map** section turns the corrections that apply into the club map's next version, after a confirm with the version's name filled in from the event. While it is saved Map mode is read-only and shows the progress; it is not an undo step, and earlier undo steps in Map mode are dropped. The original file is kept and the corrections are re-applied whenever the map is imported again, hidden objects left out and added ones kept; the event moves onto the new version and its correction list keeps only what was not saved (corrections that no longer fit the map), and other events stay on the version they took. In Settings → Maps the card shows the version, its name and "Original file; n corrections applied by Oxygen" (the download is still the original file), and whoever saved the latest version, or an admin, can delete it. See [course-editor.md](../course-editor.md) §13 "Promote" and [map-patches.md](../map-patches.md) §5.

**Drawing in Map mode** (new editor; desktop). **P**, **L** and **A** on Map mode's rail draw a point, a line or an area into the event's corrections. The inspector's **Symbols** list offers the map's own symbols and the library's (the map's own library, and ski-O symbols where the map's colours have them), searchable with swatches; a library symbol is fitted to the map's colours and scale the first time it is used, and one whose colours the map lacks is greyed out with the missing colours named. A point is one click, and the tool stays armed for the next; a symbol that turns (a crossing point, an elongated knoll) is aimed by dragging from the point. Lines and areas are drawn as course objects are: a click per node (smooth; Alt for a corner, drag for a curve), a double-click or Enter ends a line, a click on the first node closes an area; then the new object is selected. **Change symbol** on a selected object picks another symbol of the same kind, and **Rotation** turns a point whose symbol turns. Each is one undo step, saved at once, and shows in print. See [course-editor.md](../course-editor.md) §13 "Drawing" and "Symbol picker".

**Line and area operations in Map mode** (new editor; desktop). The inspector's **Map object** section has buttons for the selected line — **Reverse** (turns its direction, so dashes and symbols along it run the other way while borders and gaps stay where they were), **Split at node** (in **N**, click the node to split at: the part from the line's start stays the object and the rest becomes a new line in the same symbol; a closed loop opens there) and **Join** (then click the other line: their nearest ends are joined — ends within half a millimetre meet in one node, farther ones are joined by a straight segment — and the selected line keeps its symbol while the other is hidden; click the selected line itself to close it into a loop) — and for the selected area — **Cut hole** (draw the hole as an area is drawn; it is taken as drawn) and **Remove hole** (in **N**, click a node of the hole). Escape drops an armed Join or Cut hole. A button that does not apply says why when hovered. Each is one undo step, saved at once; a join's two changes show as two rows in Corrections. See [course-editor.md](../course-editor.md) §13 "Line and area operations".

**GPS tracks in Map mode** (new editor; desktop). A mapper's own GPS recordings, as a reference to draw the map from: the inspector's **GPS tracks** section imports one or many `.gpx` or Garmin `.tcx` files (**Import GPX/TCX…** or a drop on the section), read in the browser — one track per recorded segment (a TCX activity is one track, its laps joined), a file that is neither or holds no track reported by name, and a count of what was skipped. The list shows each track's colour, name, date, length in metres and points, how many points lie outside the map, and whether it was converted; the eye shows or hides it (remembered on this device), ✎ renames it, × deletes it (undo brings it back), and a click on the name zooms the map to it. Visible tracks are drawn over the map in their colours, thinned to what the screen can show, on screen only — never printed, never on the kiosk or to viewers. The section is off, with the reason, on a venue box (tracks live in the cloud), without permission to edit courses, and on a map without a georeference. **Convert to line** turns the ticked tracks into map lines: pick the line symbol (the ski-O track symbols come first; nothing is chosen the first time), set the smoothing (0–30 m, 10 by default) and the simplification (0.02–0.5 mm, 0.1 by default), and the lines are previewed on the map in that symbol with their node count — with a warning above 2000 nodes, where a line can no longer be edited node by node. **Snap ends to tracks** (on by default) moves each end that stops within 1.5 mm of an existing ski track line — or runs up to 1.5 mm past it — onto that line, onto its end when the two ends meet, so the tracks join up; several tracks converted together join each other in list order, and roads and paths are left alone. **Convert** writes them as the event's map corrections in one step that undo takes back; they then print, can be edited node by node, and change symbol like any line drawn in Map mode; **Snap ends** on a selected added line does the same snap later, as one undo step. A converted track stays in the list, marked, and is hidden from the map until the conversion is undone; **Show converted tracks** draws them again. The symbol, both settings and **Snap ends** are remembered on the device. The **split tool** (**T** on Map mode's rail) splits map lines and GPS tracks. On a map line: click the line to select it, its nodes show, and a click on a node splits the line there (the same as **Split at node**, in one click); the other part is then one click away. On GPS tracks it edits the ticked tracks: their points are drawn as nodes, the one under the pointer highlighted, and a click splits the track there; the two parts stay ticked, so each further click splits again — cutting out a break or a wrong turn is two clicks and deleting the middle. Drag either end along a track to trim it (drag back out to restore). Each step is one undo. **Average** makes one track out of two or more ticked passes of the same stretch: the passes are hidden (not deleted) and the stretches only one pass covered are drawn dashed; converting the average marks its passes converted too. See [course-editor.md](../course-editor.md) §13 "GPS tracks", "GPS tracks: convert", "GPS tracks: editing", "GPS tracks: junctions" and [map-gps-tracks.md](../map-gps-tracks.md) §5, §6.

The new editor's **tool rail** places a course in a row: **K** arms the control tool — a ghost circle at true size follows the pointer with the next number, the next club code and what the map says is under it ("N side of boulder"), and the map draws the course as the click will leave it — the legs into and out of the pointer with their slits and the renumbered controls, the new leg's length in metres beside it — and every click places one control into the course (ten controls are ten clicks; a click on an existing control adds that control instead). **S** places a start, **M** a finish (which ends the chain); `Ctrl+Z` steps back one placement, `Esc` / `V` / `Enter` / right-click leave the tool, and on a phone the map pans under a fixed crosshair with **Place** / **Done**. **G** opens gaps by dragging along the selected circle's rim or a leg; a snapping toggle catches a control on the nearest map feature within 0.5 mm. Dragging a control shows the length of both its legs, with a magnifier loupe above the pointer. Shift-click or Shift-drag selects several controls for one delete, add-to-course or radio. **A** draws course objects — out-of-bounds areas (striped, or cross-hatched as a dangerous area) and lines, white-out, marked routes, a toner saver around the course (smooth, 25 mm from the outermost controls, regenerated from the course on demand), and filter regions that hide or cut chosen map symbols (picked by symbol or colour, or "show only these") live as the region is drawn — the symbol list shows one entry per map symbol with its swatch (a symbol's variants and duplicates merged, hidden and unused ones left out, frames, legends and club symbols folded under Other), and *Pick from map* adds a symbol by clicking it on the map — and **T** places map text; each object has an inspector for its properties and which courses or classes it is drawn with. An area is picked up by its outline (a line by its stroke): inside an area the map pans and clicks as usual, so a toner saver round the whole course never gets in the way. A control just placed with a tool armed carries no selection ring (its purple circle is the mark, and the tool's ghost draws no second circle over the map's own); one added with *Add control* is selected with its dashed ring and the action bar. Areas and lines are smooth by default: while drawing, a click places a point that curves smoothly through its neighbours by itself (its curve follows as the next point lands or a neighbour is moved; the ends of a line stay corners), an Alt-click places a sharp corner, and a click-drag shapes the curve by hand (Shift keeps it at 45° steps); filter regions stay straight-edged. On a selected object, double-click an edge to add a smooth point (Alt for a corner), click a point and press Delete to remove it, Alt-click a point to switch it between smooth and corner, and drag its handles (Alt bends one side only) — curves print as drawn. Objects drawn before keep their corners until edited. The selection also edits a control's kind, notes and whether its number is hidden on the course. Click a leg and the inspector edits it: draw it as a line, a marked route or no line at all, bend it — **Add bend here** in the action bar adds a smooth bend (Alt-click the button for a sharp corner); drag the bend to move it and its grips to curve the leg (Alt bends one side only) — the map redraws the course as you drag, the leg, its numbers and a corridor's white band and edge following the pointer, and the change is saved once when you let go — Alt-click a bend or use its **Smooth** / **Corner** buttons in the inspector to switch it, and Delete removes the focused one; bends imported or added before stay corners until edited — and give it a **corridor** (also *Corridor on selected leg* in the **A** menu): the map is cut away in a white band beside the corridor's edge, on screen and in print. Inside a corridor the leg's own line is not drawn — the edge (a checkbox, on by default) marks the route, its lines ending on the controls, start and finish the corridor joins, and a control circle wider than the corridor opens where the corridor runs into it, as Coursecraft draws it; where a corridor ends at a control or the finish, its white band stops at the circle's middle with rounded corners, while it keeps going round a control where corridors continue — a **White opacity (%)** below 100 makes the band translucent so the map shows through it, veiled (one opacity for every band, the most transparent one in view; corridors stored before this release were reset to opaque so old maps print as before) — and the editor shows a blue dashed guide along every corridor leg of the course, which a click selects like the leg. Leg lengths and the gap tool follow the bends — the inspector's leg metres and the course total update live while you drag a bend or its grips. On a tablet a finger drags the bends and grips too: the bend rides above the finger with the magnifier loupe so the finger never hides it, a tap picks a bend, and a second finger cancels the drag. On a phone the leg's settings are shown read-only. **C** places a **crossing point** (710): on a selected leg the click puts the point there and routes the leg through it — the symbol turns along the leg, the leg's length runs through it, the description sheet gets its *mandatory crossing point* row (13.3; *mandatory passage*, 13.4, when the Leg section marks it a section), and the leg's out-of-bounds / uncrossable check is exempt at the feature it crosses. **Add map-issue point** on an empty-map click places a map-issue point (702) — where runners receive their maps, as its tooltip says — shown only in the setter's views — the editor's Course and All-controls views and the all-controls print, never on a course map. A control's kind can now be any of control, start, finish, map exchange, crossing point or map-issue point; the Controls page marks the new kinds. See [course-editor.md](../course-editor.md) §6.8. **X** places a **map exchange** in the control chain: it is a numbered control circle where the runner swaps maps, the numbering carries on after it, and the course splits into parts — the inspector's sequence shows *Part 1*, *Part 2*. **Export ▾ → This course** prints one page per part, each centred on its own part's controls and drawing only that part (the exchange circle with its number on both), while every part's description block lists the whole course with a *map exchange* row (13.5) after the exchange. Layout mode lists each part's sheet; if one is deleted, the checks say *Part 2 has no sheet* until Export makes it again. See [course-editor.md](../course-editor.md) §6.9. See [course-editor.md](../course-editor.md) §6–§7. The editor also checks the course as you set it — controls closer than 30 m (15 m on a sprint map), the same feature within 60 m, codes below 31, duplicate or upside-down-confusable codes (66 / 99), controls outside the course's sheets, numbers that overlap or are missing, missing or outdated descriptions, and legs that cross out-of-bounds or uncrossable features — in a Checks section of the inspector (click a finding to jump to it), as amber markers on the map and as a count on the top bar's course-info button, whose popover lists it beside the course's controls, length and climb. Checks are advice; nothing blocks a save. See [course-editor.md](../course-editor.md) §8.

Descriptions get a head start from the map itself: place a control and Oxygen auto-fills the top suggestion — boulder, path crossing, marsh, building — read straight out of the event's imported map document, with side-of / which-of-similar / junction symbols when the geometry supports them. Moving a control offers a single replacement suggestion if the new spot differs. The description editor shows written titles on every symbol (including column C on mobile), all eight IOF columns, and a live summary sentence. Dragging a control, a bend, a grip or an object's point with the mouse keeps the crosshair cursor and shows a magnifier loupe just above the pointer — the map at 2.5× about the dragged point, gone when you let go — so placement (and east/west details) stays precise; on a phone or tablet the loupe rides above the lifted handle instead. Dragging a control's number shows no loupe — only the number follows the pointer. Pressing Esc in the middle of a mouse drag cancels it: the control, number, bend or point goes back where it was and nothing is saved. For placing, a **placement loupe** toggle — the magnifier button in the editor's top bar (in the phone's ⋯ menu) or the key **L**, remembered by the browser — keeps the loupe over the point a click would place while a placing tool (start, control, finish, map exchange, crossing point, map text) is armed: above the pointer with a mouse, above the centre crosshair on a phone or tablet. Dragging still pans the map and a click still places. The editor's panels sit over the map, so course building keeps working in fullscreen; in the All controls view the description sheet lists every control. See [course-controls-and-matching.md](../course-controls-and-matching.md) "Description autodetect" and [bugfixes/control-description-columns.md](../bugfixes/control-description-columns.md).

The overprint also cuts itself automatically, the way a careful course setter would by hand: control circles get slits and leg lines get gaps only for compact knolls and rock objects (rocky pits, boulders, large boulders and clusters). Long cliffs, paths, walls, buildings and areas stay uncut because the colour stack already keeps their ink readable. An **Auto cuts** toolbar toggle turns the automatic decoration off for the whole event when you want unbroken purple — on both map engines, on screen and in the printed PDF; gaps you drew yourself with the new editor's gap tool stay. Each cut clears the feature's own symbol plus 0.25 mm of visible air beyond the purple line's end, so it stays readable on the printed map (on a 1:10 000 map the larger symbols get larger cuts), and existing editor courses migrate to the current cut algorithm on first view. Every event cuts against its imported map document. Imported OCAD courses keep the slits authored in the file. Control numbers are drawn above the map in upper purple, on screen and in print alike; a template can opt in to the classic white halo. Map ink that should sit above purple follows the map document's own colour stack, with the course's lower purple aligned into it under black and the upper purple on top — see `docs/course-layer.md` §1.
