# Release runbook — slice C (derived course layer and PDF)

Slice C lands on `main` the same way slices A and B did
([release-slice-b.md](release-slice-b.md)): one PR from
`vector-map-pipeline`, a merge commit, a tag (`v0.4.0`), `deploy.sh`.
The vector print path and the GL course overlay are behind the per-event
switch ([map-pipeline-switch.md](map-pipeline-switch.md)), so with the
instance defaults every event keeps the legacy editor, overlay and PDF.
Two things are **not** behind the switch and every operator will see them
(below). The point of deploying before the C-gate is the same as for B:
S2 (the print-shop preflight) and the gate's club dry run need the
released image on the club's instance.

## What this release carries

| Area | Change an operator can notice |
|---|---|
| Course cuts, **all events** | `courses.geometry` is regenerated by the course layer with **size-aware** automatic cuts (user decision 2026-10-24, `course-layer.md` §3.4): a cut now clears the feature's drawn symbol plus 0.25 mm of air, so circle slits and leg gaps are wider than before (dev copy: 142 circle cuts → 40 changed, 52 added; leg gaps 118 → 134 mm in total). `OVERPRINT_CUTS_VERSION` 3 rebuilds each stored row lazily on its first read after deploy — nothing to run, and the legacy editor / PDF show the new cuts the next time a course is opened |
| Control numbers, cliffs | library `2026.10.4`: ISOM 704 drawn in upper purple (over line art, as Mapper and Purple Pen do), no-tag cliff baselines (201 top line, 202) with round joins and ends as OCAD's set draws them — visible on `vector` events only |
| `vector` events | `maps.pdf` is produced by the new print path (`cmyk` default, embedded Liberation faces incl. Bold, `/Measure /GEO`), the course is drawn by the GL overlay in the map's colour order, `window.png` for the layout editor comes from the reference raster; `legacy` events unchanged |
| Import | importer `ocad-15` / `omap-8` (cap/join in the fingerprint, inserted purple takes the map's own purple, north-oriented point symbols turned, size-aware cut features): every production document is *stale* again — re-match before any event is switched to `vector` (step 4) |
| Dependencies | `@cantoo/pdf-lib` in `@oxygen/shared` (the `audit` CI job runs on the lockfile change) |
| CI | `qpdf` + `poppler-utils` on the runner only (S3: +14.5 MB measured, kept out of the image — decision 2026-10-24) |
| Schema | **no migration** |

Rollback: `./deploy.sh v0.3.1` (no schema change; the lazily rebuilt
`courses.geometry` rows are plain GeoJSON the old image reads as before —
its own `OVERPRINT_CUTS_VERSION` 2 rebuild then re-narrows the cuts on
the next read). `vector` events flip back per event as in slice B.

## 0. Preconditions

- `vector-map-pipeline` green on the merge commit (full AGENTS.md §6 run;
  the last PRs' CI).
- `gcloud auth login` done (`scripts/gcp/env.sh`); service in idle mode.

## 1. Land C on `main`

```bash
git fetch origin
git checkout -b release/slice-c origin/vector-map-pipeline
gh pr create --base main --title "Slice C: derived course layer and PDF (v0.4.0)" \
  --body "See docs/release-slice-c.md. No migration; size-aware cuts rebuild lazily; rollback = previous image tag."
```

Merge with a merge commit; afterwards merge `main` back into
`vector-map-pipeline` once.

## 2. Cut the release

```bash
git tag v0.4.0 <main merge commit>
git push origin v0.4.0          # release.yml retags sha-… as v0.4.0 and stable
```

## 3. Deploy

```bash
cd scripts/gcp
./deploy.sh v0.4.0              # migrate job (no-op) then the service
```

Check: an event page shows the map as before; the Courses page lists
courses with lengths unchanged (`lengthM` is not affected by the cuts);
opening a course in the legacy editor shows the wider slits.

## 4. Re-match the production documents

```bash
cd scripts/gcp
./backfill.sh --tag v0.4.0 --rematch --dry-run
./backfill.sh --tag v0.4.0 --rematch
```

Expect every pin re-matched, 0 failed, and the same hashes a dev
re-match of the same sources produces (S0's two-machine identity on
`ocad-15` / library `2026.10.4`).

## 5. S2 and the C-gate on the released instance

- **S2** (`SLICES.md`): switch one event with a pinned document to
  `vector`, download its `maps.pdf` (`cmyk`), send it to the club's print
  shop for a preflight without manual intervention; compare purple and
  brown with the current workflow's output; export the same map from
  OCAD and compare, settling the *provisional (S2)* rows of
  `map-rendering.md` §8 and `map-import.md` §3.3. Report
  `S2-print-spike.md`.
- **C-gate**: `course-maps.spec.ts` green under both projects and the
  golden PDFs on the corpus are already recorded (C3, C7, C10); what
  remains is the club dry run — one real event's maps printed from the
  vector path on the organiser's instance.

## 6. After the release

- Decision-log row: date, tag, re-match result, the S2 outcome when it
  comes.
- `SLICES.md`: the C-gate row updated with the release; slice D stays
  parked until G1 is decided.
