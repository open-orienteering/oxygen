| 2026-11-13 | G2: the patch schema and the effective document | **Questions decided by the user (the planner's recommendations); the rest decided in the row** (`map-patches.md` §1–2). (Q1) `modify` carries an optional `angle` (0.1°; absent = the document's), and so does `add`. **Extends 08 §4.7's geometry-only `modify`.** (Q2) `symbols` is a record keyed by the full library entry id the symbol was materialised from, and ops reference `{ doc: index }` or `{ patch: key }`; the combined `symbolIdx` exists only in the effective document. **Deviates from 08 §4.7** (an array appended after the document's table, ops holding a combined `symbolIdx`); G3's `symbols` defaults to `'{}'` and `mapPatch.apply` gains `putSymbols` (G3 and G8 rows amended). Decided in the row: `ops` is a record keyed by the op id (a key that is not `patchOpId(op)` is a schema error); ops carry `sourceIndex` and no `objectIndex` (**deviates from 08 §4.7**, which stored both); `add` is point / line / area with no `text` (the split's "no text creation"); geometry in document native units in the JSON projection's `[x, y(, flags)]` form; a patch symbol has no `match` and is drawn from its own `render` (new: the bridge would redraw an applied match at `documentFactor`, wrong for another library's entry, G8 / G20); hide is a per-object flag (`hidden`), not a removal, and hide / modify / resymbol of one object are independent states, all kept; added objects are appended in op-id order with `sourceIndex = 0xFFFFFFFF`, identified by their add id (their `objectIndex` holds for one patch content); every patch symbol is appended in key order, as far as u16 reaches; the effective document keeps the pinned one's `bounds` and `strings`; `applyPatch` returns `{ document, issues }` with codes `target-missing`, `symbol-missing`, `kind-mismatch`, `geometry-invalid`, `symbol-table-full`; a null, disabled or op-less patch returns the document itself; `mergePatch` (sorted keys, remove then put, a change that names one id twice refused by `patchChangeSchema`) lives in shared so G3's server and the editor run one merge; the bridge's new stat `patchHidden` is kept apart from `hidden`. | Answer 1's per-op merge with two editors: positional symbol indices would collide when two clients materialise at once and shift on every re-key (G11), while materialisation is deterministic per document, so a key per entry id makes a concurrent put the same state. Rotation lives in `attrs.angle`, not the coordinates; without it a rotated object would become hide + add and lose its `sourceIndex` identity. Stable indices and the existing readers (cuts, checks, snap, pick, the bridge) iterate the decoded document's arrays, so the effective document is a `MapDocument` with a flag rather than a filtered copy. |
