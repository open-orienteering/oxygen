# User feedback on the merged editor (2026-11-04) and the plan for rows D12–D16

Recorded by the coordinator. The user tried slice D after D5b / D8 / D9b / D11
merged (`d5db39c`) and asked for these fixes before D10, overnight, with the
plan made by a Fable planner. Open points were answered by the planner's
recommendation; each is a decision-log row marked *decided overnight — for
user review*.

## The feedback

1. Areas (the toner saver especially, which always covers every control)
   make the map impossible to pan: presses land on the area. Areas should be
   selected only by an explicit handle, or after arming, "or some other smart
   solution".
2. The toner saver should be smooth (Béziers) automatically, default margin
   25 mm.
3. Placing a control still draws a thin blue circle besides the purple one;
   the blue is not needed.
4. While drawing areas, a mode (a key held) that gives automatic Bézier
   handles from the neighbouring points.
5. Layout mode's polygon should be drawn and edited with the course editor's
   polygon functionality.
6. White-out outside in Layout: maybe it no longer has a purpose, maybe it
   does not belong in Layout.

## Plan per item

### 1 — areas swallow the map (row D12)

Root cause: a press anywhere inside a closed area resolves to the object and
arms a drag. `shared/src/render/hit-test.ts:87-94` answers distance 0 over a
fill / hatch interior, and `:100` over a closed stroke's interior with
`closedStrokeInterior` (on in `web/src/lib/editor/hit.ts:83`, needed for
control circles); `hit.ts:106` `UiArea` hits with `insideRing || ring
distance`; `components/MapViewer.tsx:979-981` builds `uiAreas` for toner saver
and filter region only; `pages/editor/tools/bindings.ts:170-176`
`selectBinding.onPointerDown` selects any `object` target and arms a drag,
`:156-160` a press on the selected object's body arms the drag;
`MapViewer.tsx:1456-1461` pans only when tool and `armEditorTarget` decline;
touch tap `:1979-1981` the same.

**Rule: closed areas are hit only along their outline; their interior is the
map.** `oob_area`, `whiteout`, `toner_saver`, `filter_region` all become
`UiArea`s (filter by `vertexRule(o.kind).closed`), `hit.ts` drops
`insideRing`, and `editorHitAt` rejects layer `object` hits for ids in
`uiAreas` (the `objects` predicate, `hit.ts:84-87`), so fill / hatch / border
never answer for them. `closedStrokeInterior` stays for control circles;
`shared/render` untouched. Lines (`oob_line`, `marked_route`) by stroke and
`text` by glyph boxes as today. In `selectBinding`, for closed kinds the
selected object's body press is not the object's: only an edge within reach
(7 px mouse, 12 px touch) or a vertex / grip is — the area moves by dragging
its edge; a drag inside pans; a click inside is a map click. D5b gestures
unchanged. Rejected: arming area selection first (one more mode; Tab and the
inspector do not list objects).

Spec: `course-editor.md` §5 (UiArea paragraph), §7 "Select" and "Editing
geometry" (pressing order, body press), §10 gestures row ("on its outline").
`docs/bugfix-editor-area-press-pans.md`. Tests: `hit.test.ts` (inside a
white-out → null; on its edge → object; a control inside an area still hits;
an oob_area with a 709.b border not hit by the stroke interior),
`bindings.test.ts` (selected area: body press declines, edge press → gesture,
vertex / grip order unchanged, a line's body press still the object's); E2E
in `course-editor.spec.ts` "tools": a drag starting inside an oob_area moves
the view (`data-centre-*`) and leaves the object; a press on its outline
selects it. Risk: an area whose edge is off-screen cannot be selected until
zoomed out (`F` fits the course).

### 2 — toner saver: smooth, 25 mm (row D13)

Today `pages/editor/tools/polygon.ts:96-108` `tonerSaverHull` (octagon per
site, convex hull `:72-88`); `EditorPage.tsx:85` `TONER_MARGIN_MM = 10`, used
at `:767-772` and `:1485-1487`; `modes/ObjectSection.tsx:100` default 10. The
layer (`shared/src/course/objects.ts:169-186`, `whiteoutOutside` `:317`) and
print already draw Béziers.

**Exact offset hull:** convex hull of the site centres (1 point → circle,
2 → stadium), offset by `marginMm`: at each hull vertex an arc of radius
`marginMm` between the incoming and outgoing edge normals, split into
≤ 90° pieces, each a cubic with handle length (4/3)·tan(θ/4)·r (the formula of
`shared/src/course/arcs.ts:17`); straight offset edges between. Each arc piece
is two `PathVertex`es (start `hOut`, end `hIn`). Move `convexHull` and the
hull to a new `pages/editor/tools/toner-saver.ts`. `TONER_MARGIN_MM = 25`
(paper mm), inspector default 25. Existing objects untouched; *Regenerate*
produces the smooth hull at the stored margin. Spec `course-editor.md` §6.4,
`course-layer.md` §8.1 `toner_saver` cell. Tests: `toner-saver.test.ts` (every
site ≥ margin from the sampled outline, tangent continuity, one site → four
quarter arcs, two → stadium, collinear, handle length, µm rounding); a
`shared/src/course/__tests__` case (a toner saver with handles yields bezier
flags in `whiteoutOutside`'s hole ring); E2E: `A` + `S` → `toner_saver` with
≥ 1 `hOut`, margin 25, and (if time) the course's `maps.pdf` has `c`
segments — else on D10's list. Put the E2E at the end of the "tools"
describe.

### 6 — white-out outside in Layout (row D14)

`fillMode: "whiteoutInverted"` = white everywhere inside the frame except the
shape (`course-maps.md:315-330`). 08 §4.5: the `toner_saver` kind is what this
fill mode grows into; 08 §5.2's Layout tool list never had it — D7 added `O`.
Existing legacy templates and fixtures carry such objects.

**Remove the `O` tool, keep the fill mode**: drop `O` from `PlaceKind`,
`LAYOUT_KEYS`, `LayoutRail.tsx`, `placeObject`, i18n (en + sv); keep
`whiteoutInverted` in `LayoutInspector.tsx` `FILL_MODES` so existing objects
stay editable and a `P` polygon can still become one (template-level ink
saving on an all-controls or class sheet). Rendering, print, schema and the
legacy editor untouched; no object changed or deleted. Spec `course-layout.md`
§2, §3 (drop the `O` row, note the fill mode), `features.md`. Tests:
`layout-model.test.ts`, `layout-bindings.test.ts`; `editor-layout-tool-O`
absent goes to D10.

### 4 — Alt = auto-smooth vertex while drawing (row D15)

Today `polygon.ts:41-69` `step` (`click` corner, `pull-handles` click-drag);
`bindings.ts:365-380` `areaBinding.onPointerDown` (has `p.alt`, unused);
preview `:347-350`. Shift = 45°, Alt = curve / retract / break in V; Ctrl is
the macOS context menu.

**Alt held at the press → smooth vertex**; a drag past 3 px is the manual pull
(Alt ignored); Alt + double-click / click on the first vertex closes with the
last and first vertices smooth. Touch: none. Spec notes the window-manager
caveat (Xfce / old KDE grab Alt+LMB). **Uniform Catmull-Rom:** `hOut_i =
(P_{i+1} − P_{i−1}) / 6`, `hIn_i = −hOut_i`; closed kinds wrap at close; an
open line's ends get no handles. Pure `smoothHandles(g, index, closed)` in
`lib/editor/geometry-edit.ts`. `PolygonState.vertices[i].smooth?: true`
(drawing-only), recomputed after every `step` from current neighbours; the
last vertex has provisional handles in the preview only (hover as next);
`move-vertex` recomputes it and flagged neighbours; `pull-handles` clears the
flag; `filter_region` ignores it; `done` strips flags — one create, one undo
entry. Spec §6.4, §6 modifier sentence, `geometryHint` (en + sv),
`features.md`. Tests: `geometry-edit.test.ts`, `polygon.test.ts`,
`bindings.test.ts`; E2E: three clicks with Alt on the second → stored
`g[1].hOut ≈ (g[2] − g[0]) / 6`.

(`model.ts:149-153` → `createObjectAt("path")`,
`lib/map-layout-editor.ts:131-146`), edited only by vertex-handle drags

**Draw:** `P` arms the course editor's `areaBinding` (`AreaKind` gains

rectangles, text, images by bounds. Spec `course-layout.md` §2, §3 (`P` row,

`layout.test.ts`; E2E "Course editor layout": `P`, three clicks + one

## Decisions for review

1. Closed areas hit by outline only, also when selected (body drag pans).
2. Selection ring hidden while an exclusive tool is armed; the placed control
   stays selected.
3. Toner saver = exact offset hull with Bézier arcs, default 25 mm paper; old
   octagons untouched until *Regenerate*.
4. Alt while placing = smooth vertex, Catmull-Rom `(next − prev) / 6`, closed
   kinds wrap, open ends corners.
5. Layout `P` drawn with the course editor's area flow; selected paths take
   D5b's gestures through `geometry-edit.ts`; Layout closed paths hit by
   outline; rectangles by bounds.
6. `O` removed from Layout; the `whiteoutInverted` fill mode stays; no data
   touched.
7. Layout stays off the phone mode switch; D-mobile decides.
