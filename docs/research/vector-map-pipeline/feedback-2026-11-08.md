# User feedback after slice F (2026-11-08) and the rows F13–F17

Recorded by the coordinator. The user tried slice F after F1–F12 merged
(`7d35d4c6`). The split, root causes and defaults below are the plan of a
Fable planning agent. Open points 1–4 went to the user. Each row's session
still runs `slice-planner` first and may reopen a default, with a reason.

## The feedback

1. "I would like to have bezier handles on the leg-bends."
2. "When doing a corridor, the leg-line in the middle shouldn't be there,
   it's just obscuring readability. So only the edge-line, if that, with a
   checkbox as now. Then ofc it needs to be possible to select the leg-line
   to get the context menu, but maybe the blue-dashed line could be there
   always."
3. "If there are forks, and all variations have the same number of
   controls, would it make sense to display the number instead of control
   code."
4. "What is even a map issue point?" — answered (IOF 702, F4). A tooltip
   rides with F14.
5. "Looking at the courses page of a forked course, it's not possible to
   see the control sequence of more than the first variation."

## Defaults and decisions (for user review unless answered)

- F13:
  - Bends are path vertices (offsets) with optional fields, so there is no
    migration.
  - The derivation flattens at 5 µm, and every consumer reads the flattened
    polyline. Legs stay polylines in the PDF; course objects keep cubics.
  - A crossing point joins a curved leg as a corner on the nearest curved
    segment.
  - Lengths follow the flattened curve.
  - Corridor runs are simplified at 20 µm only if a curved leg costs more
    than 3× a straight one.
  - Purple Pen export follows the user's answer to Q3 (default: flattened at
    0.1 mm).
- F14:
  - `legLine()` is 705 unless the leg has a corridor; 707 always draws;
    `none` never does.
  - The guide is always on wherever legs are clickable, and never in All
    variations, Layout, Field or print.
  - `G` still writes gaps on a corridor leg.
- F15:
  - The rule is the user's answer to Q4. Default: numbers when every visited
    site has exactly one sequence number across all variants; loops and
    unequal forks keep codes.
  - It applies on screen and on the `?allVariations=` page alike.
  - Labels travel as `viewOptions.labels`.
- F16:
  - The gestures are the user's answer to Q2. Default: the area tools'
    gestures — a new bend is a corner, Alt-drag pulls symmetric handles,
    grips drag one handle, Alt-click retracts.
  - Smooth / Corner buttons on the bend row cover tablets.
  - Touch bend drags stay Pending.
- F17:
  - Roots and variants share one expanded row and the same `?course=` param.
  - `CourseInlineDetail` gains `readOnly`.
  - No new button in the row.

## Questions put to the user

1. Handles on bends only (recommended), or also at the leg's ends?
2. A new bend is a corner, curved by Alt-drag as areas are (recommended), or
   smooth by default?
3. Purple Pen export of a curve: flattened at 0.1 mm (recommended), bend
   vertices only, or omitted?
4. All-variations labels: numbers only when every site has one number
   across all variants (recommended), multi-number "3/7", the first
   variant's numbers, or a toggle? And should the block list rows by number,
   where that is cheap?

## Answers (user 2026-11-08)

1. Handles on bends only.
2. **Smooth by default**: "I think I want to make areas and such default to
   smoothing as well, with alt being the modifier to make them sharp."
   - A new bend is smooth (handles from its neighbours), and Alt makes it
     sharp (F16).
   - The same inversion of D15 applies to every vertex tool, in Course
     mode's areas and lines and in Layout mode's paths. That is the new
     row **F18**, which runs before F16 so the bends use the shared
     convention.
   - Stored corners (imports, earlier drawings) stay corners.
   - Touch (F18's question, answered the same day): with no Alt on touch,
     taps follow the default and place smooth vertices (option a, not b:
     taps kept as corners). Corners on touch wait for a vertex action bar
     with Smooth / Corner buttons.
3. Purple Pen: flatten at 0.1 mm.
4. All variations: numbers when every site has one number across all
   variants, otherwise codes. The block follows where it is cheap
   (planner's default).

## Risks the implementers should know

- F13: the corridor union cost on flattened curves (`corridor.ts` builds one
  rectangle + disc per segment) — measure before deciding on
  simplification. The crossing-orientation lookup (`derive.ts:273`) finds
  the site by coordinate equality in `points`, which still holds because
  the crossing joins as a corner vertex.
- F14: the DOM mirror `course-leg` item of a corridor leg disappears with
  its layer object. If the F3 corridor E2E asserts on it, switch those
  assertions to the probe and the guide.
- F15: `numberHidden` is honoured only for a single structure today
  (`derive.ts:296`). All variations keeps ignoring it; say so in §12.7.
- F17: if `loadCourseDetail` refuses children (`COURSE_IS_VARIANT` is the
  editor-save guard, so this is not expected), widen it for reads and add
  an integration assertion.
