# SLICES — Slice D — editor phase 1 (08 §8) and layout mode (09 §4)

The full rows of this slice, moved out of [SLICES.md](../SLICES.md) on 2026-11-21. Statuses reported `review` for PRs that merged on 2026-11-20 are corrected; everything else is as it was. New rows for this slice are added here; open rows are also listed in SLICES.md.

Split 2026-10-24 from 09 §4 D, 08 §4.2–4.6 (sites, structure v1, classes,
`course_objects`, layout model), §5 (one editor, four modes — Course,
Layout, Field now; Map is slice G), §5.3 placement flow, §5.5 mobile, §5.6
checks, §6 API, §7 tests, §8 phase 1 only, 04 §7 (hit-testing, filter
regions, UI layers), 05 §5.12 (the layout editor on the GL backend, no
`window.png`) and 09 §5 (`structure` backfill, `auto_key` / `is_extra`).
Slice C made the course part of the drawing; D puts the *editor* on that
drawing: one canvas over `MapViewer`'s dynamic bucket, the course as a
stored `courses.structure` instead of a flat sequence, course-setting
objects with a scope, templates created by key, a Field mode for the
phone — and the legacy `CourseEditorPage` / `MapLayoutEditor` kept for
`legacy` events (09 §3 gates reads only). Build order the research
supports: **G1 first** (it fixes the shape of `course.setStructure` and
`control.update`, README "Decision gates"), then the schema and API (D0),
then the shell at parity with today's editor (D4) so the E2E rewrite has a
target early; filter regions (D3) are pure render work and start now.
Two rows can start at once (D0 after G1, D3 — disjoint areas); after D0:
D1, D2 (api) and D4 (web) in parallel; D5, D6, D7, D9 follow D4 (D5 and D6
share the inspector: not together; D7 and D9 are disjoint); D8 follows D7;
D11 follows D4 and G1; D10 closes the slice before the gate. Stays for
later: variations, map exchange, leg styles / corridors / crossings,
setter maps, description sheets and per-variant export (F, 08 phase 2);
the patch layer and Map mode (G, 08 phase 3); browser-side PDF (G);
deletion of the legacy editors, the SVG overlay and `courses.geometry`
(E / F); climb from contours, micro insets (08 phase 4).

Decided in this split (coordinator, 2026-10-24; a row's planner may
reopen any of them with a reason):

- **Structure schema is the whole 08 §4.3 type, phase 1 writes control
  items only.** `courseStructureSchema` (Zod) accepts the item union with
  `variation` groups and the §4.3 rules; `course.setStructure` rejects a
  group with `PRECONDITION_FAILED` ("variations arrive in slice F") so no
  half-materialised data exists and F never reshapes the column.
- **No `LegProps.path`.** C5's club comparison (`course-layer.md` §4.4):
  0 bent legs of 261 (max 0.09 mm) — the 09 §10 fidelity question is
  closed. Authored circle cuts (125 controls, 63 authored-only) become
  `controls.circle_gaps` (08 §4.2), authored leg gaps `LegProps.gaps`,
  `bends` stay in the type for marked routes. C0's interim per-leg
  `path` / `pieces` input and the viewer's reading of `courseGeometries`
  are retired by D1; an imported `ocd` course is then clipped by the
  layer's rules instead of drawn as file pieces (recorded in
  `course-layer.md` §2) — visible on paper only as the layer's own gaps
  and cuts, which the C5 report showed to be the mapper's within rounding.
- **Two specs, not one dual-run spec.** The legacy and new editors share
  no selectors, so today's `e2e/course-editor.spec.ts` is frozen as
  `course-editor-legacy.spec.ts` (`chromium`, `legacy`, deleted in F) and
  the rewritten `course-editor.spec.ts` runs the new editor under
  `map-vector` and the new `mobile` project (D10); `history/map-pipeline-switch.md`
  §7's "course-editor joins the dual-run list" is answered this way.
- **Existing map-anchored sheet / template objects are not migrated into
  `course_objects`** in D: C0 draws them, Layout mode edits them as today;
  Course mode creates `course_objects` (08 §4.5). Consolidation is F.
- **One route.** `/:nameId/course-editor` mounts the new editor when the
  event reads `vector`, pins a document and the instance flag of
  decision (2) below allows it; the legacy page otherwise. The Maps / Map
  templates pages' *Edit layout* deep-links into Layout mode
  (`?mode=layout&sheet=<seq>` / `&template=<seq>`) for such events and
  opens `MapLayoutEditor` for the others.
- **Live autodetect in the armed tool** (08 §5.3 ghost) is the server's
  `control.suggestDescription` debounced per cursor rest, not a client
  port of the autodetect over the document; "autodetect over the 02
  document" (09 §1) stays a later row.
- **Filter regions phase 1**: `clip` / `hide` over `all` \| symbol
  indices \| a colour class, with `invert` ("show only"); `hide` is a
  per-object hidden set, `clip` a clip path; the reference raster, the
  WebGL2 backend and the PDF (`W n` via C1's `clipOperators`) all take the
  region from the stream, so print equals screen by construction (04 §7).
- **Maps page stays per course**; class-override sheets are shown in the
  editor's Layout inspector only (D8), no class sub-rows on the Maps page.
- **Loupe** (D9) is Pending behind the nudge pad unless D9's planner finds
  it cheap on B2's explicit render target.

Decided before the first rows started (user, 2026-10-31, on the
coordinator's recommendations; decision log): (1) **G1** — decision log;
`course-layer.md` "Decided by the user 2026-10-31": journal-HLC version
token per course and per control, `CONFLICT` payload, field-move rebase
vs structure refresh-and-redo, presence heartbeat on the existing poll,
legacy editor sends the token, `map_patches` ops state-setting;
(2) **editor gate during D** — the temporary instance flag
`map.editor.vector` (default `false`, removed in E) in the mount rule
`vector ∧ pinned ∧ flag`, so a club event stays `vector` for the viewer
and print while the editor is unproven (D4 adds it to
`history/map-pipeline-switch.md` §1); (3) **auto-template duplicate rule** (D8)
— of several templates sharing an `auto_key`, the one with the most
sheets (`course_maps` rows) is the auto one, ties to the oldest; the
others are `is_extra`; **no renames** — templates keep their names and
the key is shown as a badge; (4) **controller capability** — a new
`courses.review` capability in D0 (`control.check` and a control's
`notes` require it; everything else stays `courses.edit`), granted to
the `courseSetter` and `eventAdmin` system groups, so a controller gets
`courses.view` + `courses.review` without `courses.edit`.
